# Internationalization (i18n)

The application is **Turkish by default with English fallback**, built as a proper
switchable i18n layer (not hardcoded Turkish). Code, identifiers, comments, and
this `docs/` folder stay **English**; only user-facing text is localized.

## Configuration

- `config/app.php`: `locale` default `tr`, `fallback_locale` `en`
  (`APP_LOCALE=tr`, `APP_FALLBACK_LOCALE=en` in every `.env` template).
- Active locale is shared to the frontend via `HandleInertiaRequests` →
  `props.locale`.

## Backend (Laravel)

- **`lang/tr.json`** — JSON catalog keyed by the English source string, for the
  `__('…')` calls in controllers/actions (flash messages, exception messages).
  English needs no file — a missing key falls back to the key text itself.
- **`lang/tr/validation.php`, `auth.php`, `passwords.php`, `pagination.php`** —
  standard framework message translations (form errors, auth, reset).
- Add a new backend string by wrapping it in `__('English source')` and adding
  the Turkish value to `lang/tr.json`.

## Frontend (Vue + vue-i18n)

- `vue-i18n` (composition mode) is registered in `resources/js/app.ts` via
  Inertia v3's `withApp` hook; the locale is synced from `props.locale` each visit.
- Catalogs: **`resources/js/lang/tr.json`** + **`en.json`**, namespaced
  (`common.*`, `nav.*`, `status.*`, then one namespace per module).
- In a component: `const { t } = useI18n()` then `t('nav.customers')`.
- Status badges resolve labels through i18n: `statusLabels.ts` returns
  `{ key: 'status.<value>', variant }` and `StatusBadge.vue` renders `t(key)`.

  `workshop`, `inventory`, `suppliers`, `quotations`, `admin`, `users`, `auth`,
  `security`, `search`, `license`, `welcome`.

## Notes

- The full backend test suite (238) is locale-agnostic — it asserts component
  names, data, enum **values**, and redirects, not display strings — so switching
  the default locale to Turkish did not change any test.
- Adding another locale later = add `lang/<code>.json` (+ `lang/<code>/…php`) and
  a `resources/js/lang/<code>.json`, then include it in `app.ts`.
